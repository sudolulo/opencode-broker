# Controlled Anthropic API Spend Gate — Authorized Design

Date: 2026-10-20. Status: parent-authorized architecture recorded for implementation; not a deployment authorization.

## 2. Guarantee and limits

Before each controlled HTTP attempt, the gateway durably reserves its full allowed liability from one authoritative wallet. The gateway sends no controlled request without that reservation. Concurrent processes cannot reserve the same money. Default operation retains the entire reservation even after a valid receipt: reserve-and-burn, not optimistic accounting.

This is NOT an unconditional provider invoice ceiling. Its financial claim assumes the provider honors the approved price ceilings, input/context bound and output limit, authenticated usage is accurate, the operator allocates exclusive funding to this gateway, the ledger is authoritative and never rolled back or cloned, and no direct-key/operator/old-software bypass exists. Removing both declarations described below is outside the guarantee. Ledger files, backups, and credentials are inside the trusted operator boundary; hashing is not tamper-proofing against that operator.

There is no verified live promotional-credit balance API. Delayed administrative cost reporting is not a spend-admission oracle; workspace-key limitations and delayed/daily aggregation make it unsuitable here. Do not invent a balance endpoint or request an administrative credential. Renewal and dynamic reconciliation are excluded.

## 3. Global constraints

- Scope is controlled Anthropic native Messages only; unrelated subscription routes remain unchanged.
- Funding is promotional-only, starts at zero, and supports exactly one funding epoch; no monthly/calendar reset, automatic $200 allowance, top-up, purchased-credit fallback, or second funding operation.
- Runtime baseline stays Node >=20.18; spend-budget functionality requires Node >=22.13 with working `node:sqlite`, subject to the parent's capability verification. No dependency addition or package engine bump.
- Import `node:sqlite` lazily only when spend-budget functionality is used; unsupported budget runtimes fail loudly and closed, while unbudgeted gateway operation still loads and functions.
- Use integer nanoUSD and BigInt arithmetic; credit/ceiling USD decimal strings round DOWN to spendable nanoUSD. Computed charges round UP if quantization is ever needed. Never use floating-point dollars. Positive decimals below 1 nanoUSD are not spendable and are rejected for positive ceilings/funding; never mint a fraction by rounding available funds upward. Rates are already positive integer nanoUSD/token strings.
- Use SQLite foreign_keys=ON, bounded busy_timeout=1000 ms, journal_mode=WAL, synchronous=FULL, BEGIN IMMEDIATE, and parameterized SQL.
- Implicit ledger opens never create schema, funds, or replacement state; only explicit offline initialization creates an empty wallet.
- Every controlled HTTP attempt has a fresh UUID and a durable DISPATCH_COMMITTED reservation before egress; no replay or timeout/expiry/crash refunds.
- Validate the final serialized request and final effective headers after all shaping, immediately before the guarded fetch; no request mutation after reservation; guarded fetch uses redirect:error.
- Refunds require reconcileUsage:true and a separately confirmed billing receipt contract; default reconcileUsage:false burns the full reservation.
- No production model prices in modules; price/model data belongs in deployment policy, with synthetic Sonnet/Opus examples confined to tests/docs.
- No commits, staging, deployment, host/service edits, credentials, or provider operations are part of this plan's execution authority.

## 4. Policy and binding

`provider.spendBudget` is a strict object: unknown properties fail validation. Fields are `ledgerPath` (absolute path), `policyID` (nonempty string), `validUntil` (UTC ISO timestamp), `ceilingUSD` (unsigned decimal string), `binding` (`providerID`, exact HTTPS `origin`, lowercase 64-hex `credentialSHA256`), `models`, optional `reconcileUsage` (boolean, default false), and optional `billingReceiptContract` (`confirmedAt`, nonempty `reference`). Each exact model entry has positive safe-integer `maxInputTokens`, `maxOutputTokens`, and `ratesNanoUSD` with positive integer decimal strings `input`, `cacheRead`, `cacheWrite1h`, `output`. Models are exact IDs, never wildcards. A confirmed contract is a locally recorded operator attestation to verified provider documentation, not something a boolean proves. The parent must establish that evidence before enabling refunds; absent evidence leaves safe mode available.

Normalization produces BigInt money/rates, validated timestamps, and `policyHash`: SHA-256 of UTF-8 deterministic JSON with recursively sorted object keys, equivalent USD decimals canonicalized to one nanoUSD representation, explicit defaults, canonical timestamps, and the complete policy including binding and ledger path. Changing policy therefore invalidates an existing funded epoch; initial delivery has no migration/refunding/reset command. Rate ceilings must cover the approved provider contract for the full policy validity interval.

The configured binding must agree with the selected provider ID, the exact actual request URL origin, and a locally computed SHA-256 of the effective outbound `x-api-key` bytes; that digest must equal both the supplied credential fingerprint and policy fingerprint. Pin `anthropic-version: 2023-06-01` and `content-type: application/json`; reject duplicate, case-colliding, or merged/ambiguous authentication. The gateway computes the fingerprint after final authentication/header shaping; it never passes raw API key bytes to the broker or records them in the ledger, diagnostics, or refusal response. Error messages must not include raw bodies, authentication headers, or key values. Policy origins reject path, query, hash, and userinfo rather than discarding them. Origin equality includes scheme and explicit/nondefault port normalization through URL.origin; redirects are disabled rather than revalidated after dispatch.

The standard public Anthropic global endpoint is the only initial paid transport. Regional/premium variants are rejected. Do not invent a geography API/header to accomplish this: validate the actual supported global origin and reject geographic overrides. Native Messages uses a pinned supported API version and no billing/experimental beta headers. The initial effective application-header allowlist is content-type, accept, anthropic-version, x-api-key, user-agent, x-request-id, traceparent and tracestate; reject other forwarded headers for this guarded route, including alternative authentication and unknown anthropic-* controls. Transport-added framing headers are not client-controlled policy inputs. **Parent integration ruling:** the global direct endpoint cannot verify proxy-only `x-fleet-health-*` context, so guarded requests never invoke healthReporter or generate private fleet/session headers. A paid request requiring health attestation, any probe/outage-health assignment, or fast scope is refused before egress. Explicit configured/incoming unsupported paid controls are refused, not stripped to make validation pass. Ordinary subscription/proxy health is unchanged. Policy validation and gateway startup diagnostics expose locally available binding errors and explicitly defer unavailable broker-registration validation to authoritative admission.

## 5. Request envelope and preauthorization

Task 1 owns a closed Messages envelope. Initially allowed top-level fields are `model`, `messages`, `max_tokens`, `stream`, `system`, `temperature`, `top_p`, `top_k`, `stop_sequences`, `metadata`, `tools`, `tool_choice`, `thinking`, and `service_tier`. The gateway pins an absent `service_tier` to `standard_only` before serialization; an explicitly different tier is refused, never silently downgraded. Every other top-level field is refused, not stripped. In particular, deny fast/premium tiers, batch, container, MCP, server tools, unknown charge-bearing options, region overrides, and beta headers. Nested structures are explicitly validated rather than trusting the top-level allowlist: only ordinary client tools with name/description/input_schema, supported client tool_choice forms, and documented text/image/tool_use/tool_result content forms are allowed. Reject server-tool `type` variants, remote resource execution, and nested unknown billing controls. Image content remains subject to the provider's enforced total input bound; it is never estimated from characters. Bounded thinking accepts disabled or enabled with positive integer budget_tokens <= max_tokens; other thinking modes require future contract review.

`max_tokens` is required, positive, a safe integer, and <= the exact model's configured maxOutputTokens. The provider-enforced full-context input cap must be <= configured maxInputTokens for every accepted request feature. If that contract cannot be established, the parent must not enable that model. Actual text length, chars/4, and count_tokens never authorize money. Supported text, image, client-tool, and tool-result blocks may carry only `cache_control:{type:'ephemeral',ttl?:'5m'|'1h'}`; its potential cost is already covered by the highest-cache reserve. Arbitrary JSON inside schema and client tool input remains inert data, not executable control.

Reserve nanoUSD:

`maxInputTokens * max(inputRate, cacheReadRate, cacheWrite1hRate) + max_tokens * outputRate`.

All arithmetic is BigInt. Reject a reservation above signed 64-bit SQLite integer range before SQL. `prepareSpendAttempt` returns the exact final body string, a SHA-256 body digest, and a request digest covering method POST, exact URL including path/query, canonical effective headers (authentication values represented only by credential fingerprint), body digest, policy hash, provider ID, and credential fingerprint. Native `/v1/messages` only is admitted; query strings and alternate paths are refused initially. Canonical header handling rejects duplicate/ambiguous authentication or billing controls. No OpenAI-only fields enter the native body.

The gateway computes this prepared object only after all existing body/header/health shaping. It verifies the prepared immutable snapshot is what fetch will send, reserves it, and immediately fetches those bytes/headers without an intervening mutation hook. Even an HTTP retry after a failed response obtains a fresh UUID and another full reservation. Only 408/409/429/5xx and fetch failures are retried on a paid lane. Incoming SDK retries are independent attempts. A financial refusal is terminal for that request: no capacity backoff or fallback onto another paid route.

## 6. Ledger and funding lifecycle

The ledger parent directory must already exist, be owned by the effective user, mode 0700, and not be a symlink. Resolve every ancestor component without following symlinks; disallow group/other-writable ancestors except a root-owned sticky directory (for example `/tmp`). The ledger and SQLite WAL/SHM files must remain private (0600 or stricter), regular files owned by that user; reject unsafe/symlink state. Same trusted-uid concurrent mutation and hostile root/operator action are outside the guarantee. Do not chmod preexisting operator files. Tests use `os.tmpdir()` private `mkdtemp` directories and do not change host permissions.

`initializeLedger` is an explicit offline operation. It exclusively creates a new file (fails if it exists), establishes schema version 1 and a zero-funded wallet bound to the policy, and closes all handles. An initialization failure removes only files created by that failed initialization and never overwrites existing state. `fundLedger` is a separate, one-time offline transaction. It requires positive `amountUSD` <= policy ceiling, nonempty unique external allocation `reference`, `confirmedAt <= now < expiresAt <= policy.validUntil`, and exact provider/origin/credential/policy binding. The operator confirms the promotional allocation is exclusive and genuinely available; the CLI does not discover or transfer credit. Expiry denies new attempts without changing balances, settlements, or liabilities. Funding remains permanently one-time even when all funds are burned or expired.

Schema version 1 uses these tables; all timestamps are integer epoch milliseconds and JSON money values are canonical decimal strings:

| Table | Columns and constraints |
| --- | --- |
| `wallet` | singleton `id INTEGER PRIMARY KEY CHECK(id=1)`, `schema_version INTEGER CHECK(=1)`, `policy_hash TEXT NOT NULL`, `provider_id TEXT NOT NULL`, `origin TEXT NOT NULL`, `credential_sha256 TEXT NOT NULL`, `funded_nano INTEGER NOT NULL CHECK(>=0)`, `available_nano INTEGER NOT NULL CHECK(>=0)`, `held_nano INTEGER NOT NULL CHECK(>=0)`, `spent_nano INTEGER NOT NULL CHECK(>=0)`, `frozen INTEGER NOT NULL CHECK(IN(0,1))`, nullable `freeze_reason TEXT`, `created_at_ms INTEGER NOT NULL` |
| `funding_epoch` | `epoch_id TEXT PRIMARY KEY` (UUID), `singleton INTEGER NOT NULL UNIQUE CHECK(=1)` referencing wallet(id), `reference TEXT NOT NULL UNIQUE`, `amount_nano INTEGER NOT NULL CHECK(>0)`, `confirmed_at_ms INTEGER NOT NULL`, `expires_at_ms INTEGER NOT NULL`, `policy_hash TEXT NOT NULL`, `provider_id TEXT NOT NULL`, `origin TEXT NOT NULL`, `credential_sha256 TEXT NOT NULL` |
| `attempts` | `attempt_id TEXT PRIMARY KEY` (UUID), `epoch_id TEXT NOT NULL REFERENCES funding_epoch(epoch_id)`, `state TEXT NOT NULL CHECK(IN('DISPATCH_COMMITTED','SETTLED','UNCERTAIN'))`, `request_digest TEXT NOT NULL`, `body_digest TEXT NOT NULL`, `model TEXT NOT NULL`, `max_input_tokens INTEGER NOT NULL`, `max_output_tokens INTEGER NOT NULL`, `rates_json TEXT NOT NULL`, `policy_hash TEXT NOT NULL`, `provider_id TEXT NOT NULL`, `origin TEXT NOT NULL`, `credential_sha256 TEXT NOT NULL`, `reserved_nano INTEGER NOT NULL CHECK(>0)`, nullable `retained_nano INTEGER`, nullable `receipt_hash TEXT`, nullable `receipt_json TEXT`, nullable `message_id TEXT`, nullable `actual_cost_nano_text TEXT`, `additional_liability_nano_text TEXT NOT NULL DEFAULT '0'`, nullable `uncertain_reason TEXT`, `created_at_ms INTEGER NOT NULL`, nullable `settled_at_ms INTEGER` |
| `violations` | `violation_id TEXT PRIMARY KEY` (UUID), nullable `attempt_id TEXT REFERENCES attempts(attempt_id)`, `kind TEXT NOT NULL`, `evidence_hash TEXT NOT NULL`, `details_json TEXT NOT NULL`, `created_at_ms INTEGER NOT NULL`; no raw request body/key data |

SQLite INTEGER values are read as BigInt with safe timestamp conversion only after range checks. Amounts/counters must fit 0..2^63-1. Additional liability and authenticated out-of-range receipt amounts use validated decimal TEXT so their recording cannot overflow the wallet and lose evidence. Foreign keys are enabled on every connection. Every mutating operation uses BEGIN IMMEDIATE and rolls back on error; each operation opens/closes its own connection through a lazy runtime loader.

On every open and within each mutation, verify schema/version, quick_check, foreign_key_check, policy/binding equality, singleton cardinality, epoch equality, monetary domains and these invariants using BigInt (not overflowing SQL SUM): available + held + spent = funded; funded equals the single epoch amount or all counters are zero with no epoch; held equals reservations of DISPATCH_COMMITTED/UNCERTAIN attempts; spent equals retained amounts of SETTLED attempts; retained <= reserved; receipt fields/state/timestamps agree. Unknown columns/schema version are not auto-migrated. Fail closed on corruption, lock timeout, missing required live WAL state, missing ledger, policy mismatch, or unsupported runtime. Absence of a WAL file after a legitimate clean checkpoint is not corruption and must not make a valid ledger unusable; deliberately lost/truncated live journal state remains outside recoverable automatic repair.

Reservation checks an unfrozen wallet, live policy and epoch, binding, sufficient available funds and unused attempt UUID. An initialized but unfunded wallet reports insufficient_funds without creating an epoch. In one transaction it inserts DISPATCH_COMMITTED, subtracts available and adds held; COMMIT must succeed before returning permission to send. Reusing an attempt ID is refused even if the payload matches. Startup/inspection never authorizes replay. A crash before fetch burns capacity by retaining its hold; a crash after fetch does the same. Time, expiry and process restart never recover money.

## 7. Receipts and settlement

Only successful complete native Messages receipts can settle. A buffered receipt needs a complete JSON message with nonempty identity, `type:'message'`, `role:'assistant'`, a content array (empty `[]` is valid, **review-fix ruling**), and a recognized nonnull stop reason (`end_turn`, `max_tokens`, `stop_sequence`, `tool_use`, `pause_turn`, `refusal`, `model_context_window_exceeded`).

**Review-fix ruling (receipt metadata):** documented usage metadata changes price, so it is neither ignored wholesale nor accepted openly. The JSON usage, `message_start` usage and every cumulative `message_delta` usage are each checked against a closed neutral allowlist:

- `service_tier`, `inference_geo` and `speed`: missing, null, `standard`, `global` or `standard` respectively.
- `server_tool_use`: missing, null, or exactly `{web_search_requests:0, web_fetch_requests:0}`. `code_execution_requests` is rejected even at 0, because its contract is not bounded.
- `output_tokens_details`: missing, null, or exactly `{thinking_tokens}`, where the value is null or a safe integer no larger than the resulting cumulative `output_tokens`. These tokens are inclusive observability, never a second charge.
- Beta `iterations`: missing, null or `[]`.

Any other key or value leaves the receipt incomplete, so the attempt stays UNCERTAIN with no refund. The four counters are never part of this allowance. Neutral metadata is dropped after validation, so canonical evidence and the ledger schema are unchanged. A stream needs one message_start, one or more ordered cumulative message_delta snapshots, message_stop, and no error; its initial stop_reason may be null, but terminal completion must be recognized and nonnull before message_stop. Event and data.type must agree. Message/model identity must be consistent and exactly match the admitted wire model ID. There are no implicit aliases and no prefix or date normalization, because provider alias mapping is unverified; policies must name the exact echoed ID. The usage contract must report required nonnegative safe-integer `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, and final cumulative `output_tokens`. Repeated delta snapshots replace previous counters, never sum, and counters may not regress. Total input is the BigInt sum of the first three; it must not exceed the reserved input bound. If cache creation breakdowns exist initially or in an update, preserve and validate them against cache_creation_input_tokens and do not add them a second time. Charge all cache creation at the frozen one-hour ceiling. Final output must be >= any initial output and <= reserved max_tokens; do not add cumulative output snapshots together.

Actual conservative cost is input_tokens*inputRate + cache_read_input_tokens*cacheReadRate + cache_creation_input_tokens*cacheWrite1hRate + output_tokens*outputRate. Costs remain integral nanoUSD; USD display rounds upward when fewer decimals are shown. No settlement uses chars/4, estimated usage, an omitted component as zero, or a nominal error cost of zero. Missing/partial/invalid usage, parser overflow, failed HTTP, disconnect, timeout, or upstream error changes DISPATCH_COMMITTED to UNCERTAIN with the entire hold retained. UNCERTAIN never automatically releases funds; the initial feature has no operator refund command. A later in-process complete authoritative receipt may settle UNCERTAIN only with matching attempt/request binding; no startup replay/recovery worker exists.

Canonical receipt hash covers attempt ID, epoch ID, request digest, policy hash, message/model identity, normalized usage and completion evidence, not raw chunks. settleAttempt revalidates the receipt against the stored attempt snapshot inside its transaction, rather than trusting a caller-supplied cost/valid flag. An identical receipt is idempotent and moves no money twice. A conflicting receipt records a violation and freezes future egress; no second refund occurs. Authentication comes from the original selected TLS transport, not a receipt supplied by a client.

If cost or token bounds exceed reservation, persist the receipt and exact additional liability (max(actual-reserved,0)), record a violation and freeze the wallet before any further admissions. Preserve the full hold, state UNCERTAIN, and refuse settlement/refund; do not clamp the receipt into a valid low cost. A token-bound violation freezes even if its dollar cost happens to fit. Failure to persist a violation fails the request closed and emits an actionable local error; the trusted, durable ledger assumption is necessary for further-process safety.

For an ordinary valid receipt, settlement removes reserved from held; with refunds disabled it adds reserved to spent, releases zero, and records actual conservative cost separately. With both refund conditions satisfied it adds actual cost to spent and reserved-actual to available. The receipt's frozen policy governs settlement even after expiry; no new calls are allowed after expiry. Matching historical settlement is allowed while frozen but cannot unfreeze it. No operation silently resets the wallet.

## 8. Bounded observation and integration

Use a single-reader pass-through stream tap, not an unbounded Response.clone tee. An incremental fatal-UTF-8 SSE parser handles CRLF and split multibyte characters and stores at most 65,536 bytes for each event plus fixed usage/identity state; an arbitrary network chunk may contain many bounded events and is never accumulated as one event. Nonterminated trailing data, including an incomplete final multibyte sequence, invalidates observation even after message_stop. Ignore ordinary content deltas after their event is bounded/parsed; do not accumulate generated text. Crossing the SSE event observation limit makes accounting permanently uncertain, continues backpressure-aware pass-through with bounded additional memory, and never refunds. **Parent JSON-memory ruling:** guarded nonstream JSON, including unsuccessful HTTP bodies, has a hard 1,048,576-byte collection cap. Crossing that cap aborts actual fetch generation and cancels the reader, retains the entire hold as UNCERTAIN, and produces a terminal error without retry. It does not continue buffering/passing through a large JSON body or hunt for a receipt. Legitimate larger paid JSON responses are deliberately refused; ordinary subscription JSON is unchanged. An unread/cancelled downstream aborts the actual upstream signal AND cancels its reader; cleanup must not keep pulling/generating to seek a receipt. Release readers and close ledger handles on every branch. The handler awaits transport cleanup, budget settlement and completion reporting before finishing; no detached settlement promise is allowed. Existing fetchImpl injection remains usable for deterministic tests.

The broker's /lease path annotates a target derived from registered manualApiTargets with `requiresSpendBudget:true` and `billingClass:'manual-api'`; callers cannot request their own paid billing classification. Preserve these on both target forms used by the gateway without sending credential bytes to the broker. The gateway requires a matching spend policy on attested manual API leases. Explicit provider.spendBudget always enforces the gate even for missing/legacy attestation. Attested missing policy, unknown/mismatched billing class, wrong provider/origin/credential, or a contradictory false/manual declaration is a terminal refusal. Explicitly test/refuse `requiresSpendBudget:false` paired with `billingClass:'manual-api'` and any unknown paid classification. A normal unbudgeted subscription target has neither paid declaration nor provider budget and follows the unchanged path.

Configuration validation must expose missing/manual mismatches at startup as well as admission; the boolean alone cannot protect deliberately edited config or obsolete binaries. There must be one documented audit of every actual upstream fetch path for the guarded provider, including retries and error fallback. No paid escape path is permitted. **Parent review-fix ruling, superseding the original 503:** refusals made before the response head use **HTTP 402**, the header `x-should-retry: false`, and the native envelope `{type:'error',error:{type:'spend_budget_refusal',code,message,retryable:false}}`. Default AI SDK and Anthropic SDK retry predicates both retry 503, and every retry is a new paid request; 402 is terminal for both. After streaming starts, the status stays 200 and an owned SSE `error` event carries the same payload. Clients that explicitly enable stream retries can still retry, but each new HTTP request is reserved independently. A guarded upstream 4xx other than 408/409/429 is terminal (402 `unsupported_request`) after bounded collection, with the UNCERTAIN full hold retained, because provider charge treatment is unverified. It gets no second lease, fetch or reservation. A local abort does not prove the provider stopped generating; the full hold covers that within the bounds. The code field distinguishes missing_policy, invalid_policy, unsupported_runtime, missing_ledger, invalid_ledger, binding_mismatch, expired, insufficient_funds, frozen, locked, unsupported_request. They are not capacity signals and cannot trigger route fallback. Status output is local, contains decimal money and digest metadata only, and explicitly distinguishes held, conservatively spent, observed cost and additional liability.
